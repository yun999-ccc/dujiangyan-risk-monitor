# 河段水过程、道路事件与后续网页联动

本版完成第一站检测与模拟的水过程和本地处置演练；未创建另外两个网页或共享后端。定位为竞赛技术方案原型，不是现场预报或导航。

## 已实现的链条

假定来水/降雨/排水 → 局部水深、流速、漫岸 → 道路采样网格受影响 → 带依据的模拟事件 → 人工确认 → 巡查任务 → 处置反馈。

道路初次积水和峰值以5模拟秒采样，观察站以每计算步记录，图表以30秒采样。时刻与单位随结果保留；不同精度不混称为实测过程。桥面资料缺失的道路不生成桥面淹没事件。没有完整路网、真实桥面或建筑覆盖时，不输出安全路线或居民人数。

## 导出与数据接口

`src/river-events.js`约定schemaVersion=1，每条事件包含：

- `id`、`scenarioId`、`riskId`、`roadId`：情景及对象身份；当前只生成water道路事件。
- `source=simulation`、`fieldCalibrated=false`：数据类型和未校准状态。
- `t`（模拟秒）、`coordinate`、`firstWet`、`peakDepth`。
- `evidence`：水深m、流速m/s、湿网格数量、5cm演示阈值与判断依据。
- `active`：当前是否还有达到阈值的采样网格，与任务状态相互独立。
- `workflow.status`：detected → confirmed → assigned → completed；日志包含模拟时刻和记录时间。
- `route.status=unavailable`及原因，不生成臆造导航。

改变参数或回放到更早时刻清空旧情景工作流。同一时刻参数对比可以保存一组基准；不同模拟时间不计算改善差值。取消新条件重算时，旧结果继续携带其实际输入；导出的parameters对应已完成结果，requestedParameters另记录编辑中的条件。浏览器保存不是服务器确认、真实警报送达或跨设备同步。

未来预警网页读取同一事件和依据，处置网页读写同一任务；需共享后端、服务端版本与权限控制，再通过实时推送同步客户端。目前只准备数据契约，没有虚构未上线网页链接。

## 验证范围

数值检查：静水无通量、均匀流与曼宁解析关系、守恒、非负水深、退水、下游倒灌、同输入回放，以及默认900秒条件下逐网格时间步长差异。0.0625s与0.03125s最大差须小于5cm、平均差小于1mm；此值是项目自动检查容差，不是实测误差标准。网页还允许对当前条件比较三个步长，较细结果也非真值。

浏览器检查：默认河段入口、输入自动重算当前时刻、旧请求取消、暂停、水面与观察点、道路定位、事件状态约束、导出、刷新恢复、回放隔离、手机横向溢出，以及原八类教学功能回归。

没有完成：实测几何输入、空间收敛、第三方模型比对、历史洪水回放校准、真实道路通行验证、完整对流动量、桥孔与管网模型。功能和时间步长检查不能替代这些条件。

## 竞赛呈现

三维展示解释空间关系；技术方案应另提供来源和假设表、模型适用范围、输入条件对比、验证记录、事件到任务的操作证据。后续取得可靠历史资料后再做现实对照，不预先编写准确率、提前预警时长或避免损失数字。
